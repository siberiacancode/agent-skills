# AsyncAPI

Maintain one AsyncAPI contract per asynchronous server, using `documentations/asyncapi.yaml` for the project's server. Document existing or feature-affected event interfaces, including WebSocket, message broker, or other message-driven channels when applicable. Describe channels, message payloads, direction of communication, authentication, and meaningful lifecycle behavior.

Reuse schemas when appropriate, align message names and payloads with code, and validate the AsyncAPI format. Preserve unrelated channels and established conventions.
