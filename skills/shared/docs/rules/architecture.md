# Architecture

Maintain `documentations/architecture.md` as a readable overview of the system's responsibilities, boundaries, integrations, and significant data flows. Describe how the relevant parts fit together, linking to source contracts and specifications instead of restating field tables or implementation instructions.

For feature updates, add only the architectural changes caused by that feature. Include internal build, deployment, or synchronization processes when they materially explain the system. Prefer brief prose and small diagrams only when they improve understanding.
