# Documentation Rules

Apply the relevant rule from `rules/` for each approved artifact: `architecture.md`, `openapi.md`, `asyncapi.md`, `sequence.md`, or `validation.md`. Use the selected feature specification for agreed requirements, existing code for established behavior, and current documents for conventions. Keep each artifact focused on its purpose and refer to existing sources instead of repeating them.

For test cases, apply `../testing/SKILL.md` and its testcase rules as the source of truth for format, naming, preconditions, and coverage.
